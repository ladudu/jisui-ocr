## 1. 目标

用约 3 周业余时间做一个 PoC，跑通：

> 手机翻书视频 → 每页最佳帧 → 日文竖排 OCR → 竖排 EPUB

并用实测数据（CER、漏页率、重复率）写技术博客。

**作品集定位**：展示「问题定义 → 选型实验 → 流水线设计 → 质量评估」的完整闭环，而不是又一个调 API 的 demo。

## 2. 要回答的 3 个问题

| # | 问题 | 在哪个阶段回答 | 用什么数字回答 |
|---|---|---|---|
| Q1 | 对日文竖排书，哪个 OCR 方案 CER 最低？（NDLOCR-Lite / PaddleOCR-VL / 云端 VLM）同一方案在竖排上比横排差多少？ | 阶段 0a（横排基线）→ 0b（竖排） | CER、每页耗时、每页成本 |
| Q2 | 只用 OpenCV 经典算法（不训练），从翻书视频切页能做到多低的漏页率和重复率？ | 阶段 2 | 漏页率、重复率 |
| Q3 | 普通 PC（无 GPU）能否跑完整条流水线？ | 阶段 0〜3 | 各阶段在 CPU 上的耗时 |

## 3. 范围

**做**：CLI 流水线（阶段 0〜2），第 3 周加 FastAPI + Vue 3 的左右对照校对页和竖排 EPUB 输出。

**不做（PoC 阶段）**：
- 书脊附近的去弯曲（dewarp）、手指遮挡检测
- 多用户、登录、对外提供扫描服务（版权原因）
- 有声书（TTS）、图表和公式还原

**以后再说**：dewarp、手指遮挡检测、低置信度页的云端兜底（hybrid）、C# + ONNX Runtime 重写 OCR 调用层。

## 5. 技术选型（初版，阶段 0 后复核）

| 层 | 选型 | .NET 类比 |
|---|---|---|
| 流水线 / CV | Python 3.12 + uv、OpenCV、ffmpeg | Console App + NuGet |
| OCR | NDLOCR-Lite 主力（CPU 可跑），PaddleOCR-VL 备选，Claude 作对照组；不用 DeepSeek-OCR（竖排差；横排虽强，但需要 GPU，0a 不加） | — |
| API（阶段 3） | FastAPI | ASP.NET Core Minimal API |
| 任务队列（阶段 3） | SQLite 队列表 + 后台 worker | Hangfire |
| 存储 | SQLite + 本地文件系统 | SQL Server LocalDB |
| 前端（阶段 3） | Vue 3 + Vite（PWA） | — |
| 输出 | pandoc（Markdown → EPUB，`writing-mode: vertical-rl`、`page-progression-direction="rtl"`） | — |
| 部署 | Docker Compose，家里服务器 | — |

各 OCR 引擎的依赖互相冲突，所以分开装：本项目 venv（评测）、`uv tool`（NDLOCR-Lite）、`.venv-paddle`（PaddleOCR-VL）。

## 6. 评估指标

| 指标 | 定义 | 阶段 |
|---|---|---|
| CER | 编辑距离 ÷ ground truth 字符数（NFKC、去空白换行、去青空文库ルビ记法后） | 0, 1 |
| 阅读顺序错误 | 竖排列顺序被打乱的页数（人工标注） | 0 |
| 漏页率 | 没切出来的页 ÷ 总页数（比对印刷页码） | 2 |
| 重复率 | 重复输出的页 ÷ 总输出页数 | 2 |

拍摄条件固定（同一部手机、60fps、室内自然光），写进博客。

## 7. 版权与合规（硬性约束）

- 自己购买的书、自己扫、自己和家人用 → 私的複製（著作权法第 30 条第 1 项），合法
- 代扫 / 做成替别人扫书的服务 / 把扫描数据发给他人或公开 → 违法
- **仓库、博客里公开的一切图片和文本，只来自版权已过期的书或自己写的文档**
- 用自己的有版权的书做实验时，只公开 CER 等数字，不公开原文和页面图
- `data/`、`outputs/` 已在 `.gitignore` 中排除
- 页面图片发给云端 API 属灰色地带（风险较低，推断）；只在阶段 0 少量试用，并确认服务商的数据使用政策

（不是法律意见；若以后做成对外服务，先咨询知识产权律师。）

## 8. 风险

| 风险 | 应对 |
|---|---|
| 视频帧比照片模糊，OCR 变差 | 阶段 2 对比「视频帧 vs 照片」CER；试 4K / 60fps / 高码率 |
| 竖排列顺序、ルビ、穿插横排被打乱 | 以 NDLOCR-Lite 为主；单独报告「阅读顺序错误」 |
| LLM 校对编造内容 | 只输出 diff，人工确认后合并 |
| PaddleOCR-VL / 云端需要 GPU 或付费 | 主线只用 CPU；云端只在阶段 0 少量试用 |
| 业余时间不足 | 阶段 0 的对比结果本身就够写一篇博客，先发 |
